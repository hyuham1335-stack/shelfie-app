# UI 디자인 가이드

## 디자인 원칙
1. **책 표지가 주인공이다.** 화면의 시각적 무게는 표지 이미지가 갖는다. UI 자체는 종이처럼 물러나 있어야 하고, 표지보다 채도가 높은 요소를 만들지 않는다.
2. **사실과 해석은 눈으로 구분된다.** 알라딘에서 온 사실(제목·저자·쪽수·평점)과 Claude가 쓴 해석(한줄평·추천 이유)은 절대 같은 층위로 렌더하지 않는다. 사용자가 "이건 검증된 정보, 저건 AI 의견"을 라벨을 읽지 않고도 알아볼 수 있어야 한다.
3. **못 한 일을 숨기지 않고, 이유를 정확히 말한다.** 미확인 책은 접거나 축소하지 않고 확인된 책과 같은 화면에 둔다. 실패를 드러내는 화면이 실패를 감추는 화면보다 신뢰를 얻는다. 다만 드러내는 것만으로는 부족하고 **사유가 사실이어야 한다** — 알라딘이 멈춰서 못 찾은 책에 "절판일 수 있어요"라고 쓰면, 없는 책을 지어내는 것과 같은 종류의 거짓말이 된다 (ADR-005).
4. **한 손으로 쓴다.** 책장 앞에 서서 한 손으로 폰을 든 상태가 기본 사용 자세다. 주요 버튼은 화면 하단, 터치 타깃은 최소 44×44px.

## AI 슬롭 안티패턴 — 하지 마라

## 컴포넌트

### 카드
확인된 책과 미확인 책은 **모서리 반경을 다르게** 해서 형태로도 구분한다. 균일한 반경은 금지 사항이기도 하다.

```
확인된 책:  rounded-md bg-white border border-[#E5E1DA] p-4
미확인 책:  rounded-sm bg-[#F5F2ED] border border-dashed border-[#B45309]/40 p-4
추천 카드:  rounded-lg bg-white border border-[#2F5D50]/30 p-5
```

### Claude 생성 텍스트 블록
사실과 해석을 가르는 핵심 장치다. 한줄평과 추천 이유는 **반드시** 이 형태로만 렌더한다.

```
border-l-2 border-[#2F5D50]/40 pl-3 text-sm text-[#6B6560] italic
라벨: text-[11px] uppercase tracking-wide text-[#8C8681] not-italic — "AI 한줄평" / "추천 이유"
```

### 버튼
```
Primary:   rounded-md bg-[#2F5D50] text-white px-5 py-3 hover:bg-[#264A40]
Secondary: rounded-md bg-white text-[#1A1A1A] border border-[#E5E1DA] px-5 py-3 hover:bg-[#F5F2ED]
Text:      text-[#6B6560] hover:text-[#1A1A1A] underline underline-offset-2
```

### 입력 필드
```
rounded-md bg-white border border-[#E5E1DA] px-4 py-3 text-[#1A1A1A]
placeholder:text-[#8C8681] focus:border-[#2F5D50] focus:outline-none
```

### 배지
```
미확인:     rounded-sm bg-[#B45309]/10 text-[#B45309] text-xs px-2 py-0.5
평점:       text-[#6B6560] text-xs — 별 아이콘 없이 "독자 8.6" 형태로 출처를 드러낸다
직접 확인:  bg-[#F2EFEA] text-[#6B6560] text-xs px-2 py-0.5 — 중립색. 주의색을 쓰지 않는다
```

"직접 확인"은 사용자가 재검색으로 찾아낸 책(`/api/books/resolve` 승격분)에 붙는다. **주의색을 쓰지 않는 것이 규칙이다** — 그 책은 알라딘 대조와 서명을 똑같이 통과했고, 사용자가 직접 확인했다는 사실은 결함이 아니라 출처 정보다. `lookup_failed` 배지에 중립색을 쓰는 아래 규칙과 같은 계열이다: **색은 심각도를 말하는 자리이지 분류를 말하는 자리가 아니다.**

### 미확인 사유 문구

사유 4종은 **서로 다른 문장**으로 표시한다. 특히 `lookup_failed`에 절판·원서 안내를 쓰면 시스템 문제를 데이터 문제로 설명하는 것이 되어, "왜 빠졌는지 보여준다"는 원칙을 정면으로 어긴다 (ADR-005).

| `reason` | 배지 문구 | 설명 문장 | 사용자가 할 수 있는 것 |
|----------|-----------|-----------|------------------------|
| `unreadable` | 못 읽음 | "책등 글자를 읽지 못했어요" | 제목 직접 입력 |
| `no_match` | 검색 결과 없음 | "알라딘에서 찾을 수 없는 책이에요 (원서·절판일 수 있어요)" | 제목 고쳐 재검색 |
| `ambiguous` | 후보 여럿 | "비슷한 책이 여러 권이에요. 어느 쪽인가요?" | **후보 목록에서 바로 선택** (재검색 불필요) |
| `lookup_failed` | 확인 못 함 | "지금 확인할 수 없었어요. 잠시 후 다시 시도해 주세요" | 재시도 |

- `lookup_failed` 배지는 미확인 앰버(`#B45309`)가 아니라 **중립(`#6B6560`)** 을 쓴다. 사용자 책장의 문제가 아니라 우리 쪽 문제이므로, 주의를 요구하는 색으로 표시하지 않는다.

### 에러 배너

```
컨테이너: rounded-md bg-white border border-[#B3261E]/30 p-4 space-y-2
메시지:   text-sm text-[#1A1A1A]
요청 ID:  text-[11px] font-mono text-[#8C8681] — "오류 ID: {requestId}"
액션:     Secondary 버튼("다시 시도"), 상황에 따라 Text 버튼("처음으로")
```

- **요청 ID가 있으면 반드시 노출한다.** 서버 로그를 이 값으로 찾도록 설계돼 있으므로(`/docs/TRD.md` 6.4), 화면에 없으면 상관관계 ID 규칙이 무의미해진다. 탭하면 클립보드에 복사된다.
- **없으면 그 줄 자체를 그리지 않는다.** 네트워크가 끊겨 응답 본문이 아예 없었던 때는 요청 ID가 없다. 그때 `(없음)` 같은 문자열을 지어내 자리를 채우지 마라 — 사용자가 그것을 복사해 문의하면 우리도 찾을 수 없는 값이고, **없는 것을 있는 것처럼 보이게 만드는 것**이다.
- 모델이 생성한 문장이나 내부 에러 원문을 배너에 넣지 않는다. 정해진 문구만 쓴다.
- 503(`SERVICE_DISABLED`)일 때는 재시도 버튼을 **감춘다.** 눌러도 달라지지 않는 버튼은 없느니만 못하다.
- 재시도 간격(FR-010)을 기다리는 중에는 **감추지 않고 비활성**한다. 감추는 것과 비활성은 다른 말을 한다 — 감추면 "이 길은 없다"이고, 비활성은 "이 길은 있는데 지금은 아니다"다. 대기는 곧 끝나므로 버튼이 사라졌다 나타나면 화면이 흔들리고, 사용자는 자기가 무엇을 잘못했는지 되짚는다. 남은 시간을 함께 보여 준다.

### 부분 실패 배너

```
rounded-md bg-[#F5F2ED] border border-[#E5E1DA] px-4 py-3 text-sm text-[#3D3A36]
액션: Text 버튼 — "이 사진만 다시 시도"
```

- 확인된 책 목록 **위**에 둔다. 결과를 다 본 뒤에 실패를 알리면 이미 목록이 전부인 줄 안다.
- 문구는 "사진 3장 중 1장은 읽지 못했어요"처럼 분모를 함께 밝힌다. 응답의 `failedPhotoIndexes`로 실패한 사진만 골라 재시도한다.

### 안내 문구 (Notice)

목록에 딸린 짧은 사실 안내. 에러가 아니므로 색을 쓰지 않는다.

```
text-xs text-[#6B6560] — 목록 하단 또는 섹션 제목 옆
```

| 상황 | 문구 |
|------|------|
| `overflowCount > 0` | "50권까지만 보여드려요 ({n}권 더 있음)" |
| `unidentifiedOverflowCount > 0` | "못 읽어낸 책 {n}권은 목록에서 생략했어요" — 미확인 섹션 하단에 둔다 |
| `shortfall: true` | "확인된 책이 {n}권뿐이에요. 책장을 더 찍으면 더 잘 고를 수 있어요" |
| 재추천 5회 소진 (FR-010) | "기분을 바꿔 적어 보세요" — 버튼은 비활성 상태로 남긴다 |
| 분석 재시도 대기 중 (FR-010) | "{n}초 뒤에 다시 시도할게요" — 간격은 0초 → 5초 → 15초. 경고색도 `role="alert"`도 쓰지 않는다 |
| 무관 판정 2회 뒤 3번째 입력 (US-003) | "그대로 다시 누르셔도 돼요. 저희가 잘못 읽었을 수 있어서 이번에는 적으신 그대로 골라 드릴게요 — 다만 고른 이유가 덜 들어맞을 수 있어요" — 중립 톤. 요구를 반복하지 않고, 결과 품질이 낮을 수 있음도 숨기지 않는다 |
| 500 에러 (`INTERNAL_ERROR`) | "문제가 생겨 중단했어요. 잠시 후 다시 시도해 주세요" — 502와 같은 배너를 쓴다 |

`unidentifiedOverflowCount`에 문구가 없으면 화면은 **아무것도 그리지 못한다.** 미확인 100건 상한에 걸려 잘린 책이 있는데 그 사실을 말하지 않는 것은 "못 한 일을 숨기지 않는다"를 정면으로 어긴다 — 확인된 책의 절단(`overflowCount`)만 알리고 미확인 쪽은 조용히 버리면, 숨기는 대상이 하필 **우리가 실패한 쪽**이 된다.
| 확인 0건·미확인만 | "읽어낸 책을 알라딘에서 확인하지 못했어요" (중앙 정렬 빈 상태 레이아웃) |

## 레이아웃
- 전체 너비: `max-w-md` (모바일 우선. 데스크톱에서도 이 폭을 유지해 한 손 사용 레이아웃을 깨지 않는다)
- 정렬: 좌측 정렬 기본. 중앙 정렬은 빈 상태·에러 화면에만
- 간격: 카드 내부 `gap-2`, 카드 사이 `space-y-3`, 섹션 사이 `space-y-8`
- 표지 이미지: 고정 폭 `w-16`, 비율 유지(`object-contain`). 표지가 없거나 **URL이 있어도 로드에 실패하면**(404·네트워크) 같은 폴백 — 제목 첫 글자를 `#F5F2ED` 배경에 표시한다. 깨진 이미지 아이콘을 노출하지 않는다
- 긴 제목·저자는 잘라 낸다: 제목 `line-clamp-2`, 저자·출판사 `line-clamp-1`. `max-w-md` 폭에서 카드 높이가 들쭉날쭉해지면 목록을 훑기 어려워진다. 전체 제목은 `title` 속성으로 남긴다
- 주요 CTA는 하단 고정(`sticky bottom-0`), 배경 `#FAF9F7`에 상단 구분선

## 애니메이션
- `fade-in` (0.2s ease-out) — 분석 결과·추천 카드가 나타날 때만
- 스켈레톤은 펄스 없이 정적인 `#F5F2ED` 블록으로 표시한다
- 그 외 모든 애니메이션 금지. 특히 카드 hover 시 이동·확대·그림자 변화 금지

## 아이콘
- SVG 인라인, `strokeWidth 1.5`, 크기 16 또는 20
- 아이콘 컨테이너(둥근 배경 박스)로 감싸지 않는다
- 사용처를 카메라·재시도·닫기·체크 4종으로 제한한다. 책·별·AI를 상징하는 장식 아이콘은 쓰지 않는다
- 표지 이미지의 `alt`는 "{제목} 표지" — 정보이므로 빈 `alt`를 쓰지 않는다
